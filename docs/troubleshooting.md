# Troubleshooting

[← Back to README](../README.md)

Problems with installing and using Core. Framework-specific problems are listed at the end of each setup guide: [Mobile](mobile-automation.md#11-common-problems-and-solutions) · [Web](web-automation.md#11-common-problems-and-solutions) · [API](api-automation.md#11-common-problems-and-solutions) · [Database](database-automation.md#11-common-problems-and-solutions).

## Installation and authentication

| Symptom                                                                               | Cause                                                                                             | Fix                                                                                                                                                                                   |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm error code E401` / `401 Unauthorized`                                            | `NODE_AUTH_TOKEN` is empty in this terminal, or the token expired or was revoked.                 | Set the token again in the same terminal ([how](getting-started.md#option-a-install-from-github-packages)). `node -e "console.log(!!process.env.NODE_AUTH_TOKEN)"` must print `true`. |
| `npm error code E403` / `403 Forbidden`                                               | The token lacks `read:packages`, needs SSO authorization, or your account cannot see the package. | Create a token with `read:packages`. If GitHub shows **Configure SSO** next to the token, authorize it. Ask the owner for access to a private package.                                |
| `E404 Not Found` with `registry.npmjs.org` in the URL                                 | npm does not know the scope belongs to GitHub, so it searched the public registry.                | Check that `.npmrc` is in the project folder, next to `package.json`, and contains both lines from the guide.                                                                         |
| `E404 Not Found` with `npm.pkg.github.com` in the URL                                 | The version is not published, or it is private and your token cannot see it.                      | Check the package page on GitHub, or use a [local package file](getting-started.md#option-b-install-from-a-local-package-file).                                                       |
| `npm error code ENOENT` (after `tarball data ... seems to be corrupted`) for a `.tgz` | The path to the package file is wrong.                                                            | Run `npm pack` again in the Core folder and copy the exact file name it prints. Use a path relative to your project folder, or an absolute path.                                      |
| `npm warn install-scripts ...`                                                        | Newer npm versions skip some packages' install scripts until you approve them.                    | The setup guides do not need those scripts; the warning can be ignored.                                                                                                               |
| `npm warn EBADENGINE ... required: { node: '>=22' }`                                  | Node.js is older than 22.                                                                         | Install Node.js 22 or later and check with `node -v`.                                                                                                                                 |

## Node.js and TypeScript

| Symptom                                                                 | Cause                                                                                          | Fix                                                                                                                                 |
| ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `ERR_PACKAGE_PATH_NOT_EXPORTED` or `require() of ES Module`             | A CommonJS project loads Core with `require()` on Node.js older than 22.12.                    | Upgrade Node.js to 22.12 or later, or switch the project to ES modules with `npm pkg set type=module`.                              |
| `ERR_UNKNOWN_FILE_EXTENSION ".ts"` or `SyntaxError` on type annotations | Node.js is older than 22.18, so `node file.ts` cannot run TypeScript.                          | Upgrade Node.js to 22.18 or later, or compile with `tsc` and run the `.js` output.                                                  |
| `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`                                     | The file uses syntax Node.js cannot strip, such as `enum` or constructor parameter properties. | Rewrite that part with plain fields and objects. `"erasableSyntaxOnly": true` in `tsconfig.json` reports these places in `npx tsc`. |
| `Cannot find module './src/support/core.js'` when using `node`          | Plain `node` does not map `.js` imports to `.ts` files.                                        | Run the code through your test runner, or import with the `.ts` extension as in the [database guide](database-automation.md).       |
| `Cannot find name 'NodeJS'` or missing `AbortSignal` types              | `@types/node` is not installed.                                                                | `npm install --save-dev @types/node`                                                                                                |
| `Top-level 'await' expressions are only allowed when ...`               | `tsconfig.json` targets an older module system.                                                | Set `"module": "NodeNext"` and `"target": "ES2022"`, as in [Getting started](getting-started.md#3-prepare-your-project).            |
| `ConfigLoader.load` rejects a Zod schema in TypeScript                  | The schema comes from Zod 3.                                                                   | `npm install zod@4`                                                                                                                 |

## Settings and environment variables

| Symptom                                          | Cause                                                                                                                                 | Fix                                                                                                                                          |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `.env` values are ignored                        | Commands run from another folder, the variable is already set in the shell, or an object was passed to `new EnvironmentManager(...)`. | Run from the folder that contains `.env`. Shell and CI variables always win. Only `new EnvironmentManager()` without arguments reads `.env`. |
| `FrameworkError: Unsupported NODE_ENV value: qa` | `NODE_ENV` has a name Core does not accept.                                                                                           | Use `development`, `staging`, `production`, or `test`. Put other names in your own variable; see [Configuration](configuration.md).          |
| `Configuration validation failed: logLevel: ...` | `LOG_LEVEL` is not one of `fatal`, `error`, `warn`, `info`, `debug`, `trace`, `silent`.                                               | Fix the value in `.env` or in the shell.                                                                                                     |
| `MISSING_ENVIRONMENT_VARIABLE`                   | A variable read with `env.require(...)` is missing or blank.                                                                          | Add it to `.env`, or set it in the shell or CI. The message names the variable.                                                              |
| `INVALID_ENVIRONMENT_VARIABLE`                   | A typed getter (`getNumber`, `getBoolean`, `getUrl`, `oneOf`) received a value in the wrong format.                                   | The message names the variable and the expected format. The value itself is never printed.                                                   |

## Still stuck?

Open an issue at [github.com/martirosyan0017/qafundix-core/issues](https://github.com/martirosyan0017/qafundix-core/issues) with your Node.js version (`node -v`), operating system, the command you ran, and the full error. Remove tokens, passwords and internal URLs before posting.
